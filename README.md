# SAQ — уведомления и поручения

Отдельный интерактивный макет, подготовленный 05.10.2026 по пяти репозиториям SAQ. Готовые модули не изменяются.

**Основное решение:** уведомления и поручения связаны, но являются разными сущностями. Из обоих мест пользователь попадает в один документ. Прочтение уведомления не выполняет поручение и не подтверждает ознакомление.

- Колокольчик справа: счётчик непрочитанных, последние 5 сообщений, фильтры, переход к полному списку.
- Общий раздел: поиск, фильтры по модулю и типу, прочтение, срок связанного поручения.
- Поручения по образцу профконтроля: «Входящие / Отправленные», поиск, состояние отправленных документов, таблица и ссылка «Перейти».
- В меню только «Поручения» и «Уведомления». Модуль указывается как источник сообщения, без отдельных разделов в меню.
- 10 вымышленных тестовых пользователей. Выбор пользователя расположен над рабочим разделом, как в профконтроле.
- В уведомлении обычный текст о событии и ссылка «Перейти к документу». Согласование, возврат и другие решения доступны только на отдельной странице документа соответствующего модуля.

## Границы

Это самостоятельный frontend-макет с вымышленными данными. Состояние сохраняется в `localStorage` текущего браузера. Нет серверной авторизации, настоящей ЭЦП, реальных отправок, почты и интеграций с пятью модулями. Все действия и сроки — демонстрационные. Выбор пользователя не является механизмом защиты данных.

Документы в макете сокращены для проверки навигации. Производственная система должна открывать документы соответствующего модуля, проверяя актуальные полномочия, редакцию и состояние поручения на сервере. Старые версии документов в этом макете полностью не воспроизводятся; их неизменяемые снимки обязательны при интеграции.

## Запуск

Node.js 22+; сторонние зависимости не требуются.

```bash
npm run dev
npm test
npm run build
```

Макет доступен на `http://localhost:4173`. Сборка создаёт статические файлы в `dist/`. `vercel.json` содержит настройки сборки.

## Что посмотреть

1. Согласующий → колокольчик → программа аудита → согласовать. Затем выбрать утверждающего: появляется следующий этап.
2. Представитель объекта → аудиторский отчёт. Открытие меняет только прочитанность. После отдельного подтверждения аудитор получает результат.
3. Специалист по перечню → отбор СУР → исключить объект с обоснованием → завершить. Аналитик СУР получает результат с количеством включённых и исключённых объектов.
4. Согласующий → запрос по возражению → вернуть с причиной. Исполнитель рабочего органа получает поручение на доработку.
5. Член комиссии → подтвердить участие. Исполнитель рабочего органа получает ответ.
6. «Отметить все прочитанными» обнуляет счётчик колокольчика, сохраняя поручения.

Для повторного просмотра: «Перезапустить демо» в шапке.

## Визуальный образец

Шапка, компактное раскрываемое меню, логотип и блок выбора пользователя приведены к профконтролю. Структура «Поручений» адаптирована из `src/shared/workflow/ApprovalInbox.tsx`, а `workflow.css` перенесён из одноимённого файла `saq-prof-test` (редакция `0804d0e5ff9c83de568931c88a6d7e51dd94cb52`). Решения принимает отдельная форма документа; список поручений выполняет только навигацию.

## Компактная лента и страницы

«Непрочитанные» открываются первыми в ленте и колокольчике. Полный список показывает 10, 25 или 50 записей на странице; колокольчик — пять последних по выбранной вкладке. Длинный текст раскрывается в строке, решения доступны только в документе. У согласующего есть 32 дополнительных вымышленных сообщения из истории для проверки страниц. Обновление добавляет их один раз и сохраняет предыдущие демонстрационные решения.

Цветовая раскраска уведомлений отключена: белые строки, нейтральные значки и метки модулей. Архива нет; все сообщения, включая ранее архивированные в демо, доступны во вкладке «Все». Прочитанность и решения сохраняются.

В уведомлениях и колокольчике только две вкладки: «Непрочитанные» и «Все». Пометки и счётчик «Требует действия» убраны; назначенные задания доступны в «Поручениях».
